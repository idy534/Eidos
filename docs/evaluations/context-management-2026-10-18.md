# 上下文管理验证记录 · 2026-10-18

本轮修复把圆环、详情总量和内容分项统一到当前 Run 的同一份上下文投影。系统保留 Provider 实测优先的规则。系统不会把累计消费量当作当前占用，也不会把超过设置上限的百分比截成 100%。

源码确认了三个显示问题。旧圆环把百分比限制为 100%。旧详情使用 Provider 总量，但分项仍使用未校准的词表数值。圆环与详情还分别读取数据，两个入口不能保证展示同一份投影。静态截图不能确定两个读数各自对应的 Snapshot。

Runtime 在压缩后使用原有工具、规则、Skill 和仓库上下文重建投影，并在 SQLite 中保存 ContextPlan 与刷新 Event/Outbox。系统不为统计伪造模型请求。下一次请求返回前，系统显示新投影的估算。下一次请求完成后，系统使用该请求的 Provider 数值。重建失败时，系统显示暂无统计，旧请求总量不能冒充压缩后的占用。Renderer 共用一次 `context/details` 响应，并合并密集刷新，避免流式通知堆积请求。分项 Token 的整数分配与百分比舍入均保持合计一致。子 Agent 定义和用户图片的参考分项也有独立测试。

本地日志确认了另一处压缩失败：`critical summary facts exceed context budget`。旧摘要反复复制不确定工具副作用的长说明。新摘要从持久来源重建短引用，保留 Item、ToolCall、工具和不确定状态。原始结果保持完整。回归覆盖 54 个工具结果和三轮连续压缩，并验证摘要与保留窗口共同覆盖来源。模型没有选中的历史用户报告也继续保留。

本轮复用现有 Pydantic AI Model API、SQLite/Event/Outbox、ContextPlan 和 tiktoken。系统没有增加生产依赖、数据库 Schema、Worker 或第二套状态权威。旧 Plan 与 Snapshot 继续读取，原始历史不会被删除。Desktop 与 Runtime 需要一起更新，当前启动的旧 Runtime 需要重启才能加载代码。内置模型的窗口编辑入口仍属于规划需求。

当前追加 Diff 涉及 41 个文件，其中三个 JSON 文件保存原始评测记录，两个文件是生成契约。其余改动覆盖统计、压缩、队列刷新、定向测试与文档。系统没有进行目录搬迁，也没有改变权限、审批或工具执行规则。

本轮没有运行 Full Suite、DMG 验证或真实仓库长期任务验收。合成回放与一个隔离修复样本不能证明所有模型的压缩质量、长期任务成功率或费用目标。五步方案中的工程能力和基础评测已接入；长期产品验收仍需要真实任务样本。
