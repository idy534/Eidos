评审会话切换卡顿修复

设计要点

  • 连续的工具调用合并为一组，默认折叠成一行摘要：「读取 4 个文件 · 搜索 3 次 · 运行 6 条命令」。模型的叙述文字仍然在组与组之间正常显示，保持阅读节奏。
  • 进行中的一组：前置转圈图标，摘要变成流光的「正在运行 git diff …」，用户不展开也知道在做什么。
  • 展开后是紧凑的 28px 行列表：左侧 1px 细线作为引导，图标 + 动词（灰）+ 目标（深色，路径/命令用等宽字体）。超过约 9 行时限高滚动，上下渐隐遮罩，不再把对话顶出屏幕。
  • 单行再展开才看详情：命令输出、编辑 Diff、报错。沿用现有 shell-result 卡片的底色与圆角，但去掉 “Shell” 标题，缩小内边距。
  • 失败只提示不打断：摘要末尾一个红色小胶囊「1 失败」，展开后该行文字变红。
  • 仅用 Eidos 现有 token（--accent、--line、--apple-spring、圆角体系），不新增色相；只补 3 个中性灰 token。无焦点环，hover 底色即反馈。
