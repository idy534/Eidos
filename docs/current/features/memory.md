# 当前记忆系统

读者可以在[记忆架构专题](../../architecture/memory.md)查看发布与撤销结构。Eidos 使用 `MEMORY.md` 短索引和主题 Markdown 笔记。主 Run 在当前对话中即时保存，模型会等待工具结果。系统没有闲置后生成记忆、后台模型整理、候选确认或历史回填流程。

记忆提供历史资料。当前用户指令和已经核实的现状优先。记忆不授予文件、网络或工具权限。

## 数据与升级

`state.sqlite` schema v43 是唯一业务事实来源。它保存作用域、模式、笔记版本、来源记录、操作结果、归档状态与隐私撤销版本。正文位于数据目录 `memory/scopes/<scope UUID>/revisions/<revision UUID>.md`。用户和模型使用相对笔记路径。SQLite 把路径映射到有效版本；孤立文件不能成为记忆。

Runtime 按生效笔记的路径和摘要生成 `MEMORY.md`。索引最多 200 行、约 24 KiB，末尾保留搜索和分页提示。模型不维护另一份摘要文件，也不直接修改派生索引。归档笔记不进入索引。

v39→v40 按此前明确的开发期决策清空旧记忆，不转换旧正文。迁移保留聊天、项目和其他业务数据。v40→v41 修复旧来源撤销，v41→v42 移除会话级临时记忆模式。

v42→v43 保留已有笔记、历史版本、模式和已撤销记录。升级新增归档标记，并把聊天来源变更触发器改为只维护来源记录。升级不会恢复已遗忘或已隔离的旧记忆。失败时，SQLite 会回滚字段、触发器和 schema 版本。旧 Runtime 不能打开 v43 数据。

目录和文件继续使用私有权限、目录 FD、`O_NOFOLLOW`、普通文件与硬链接检查、fsync 和原子发布。正文读取检查保存的大小与 mtime。该检查不能识别主动保留两者的篡改。

## 范围、模式与来源

全局与项目范围由服务端的项目身份决定。Projectless 的当前范围是全局。项目 Worktree 共享项目记忆。主 Run 可以向模式为 auto 的全局或当前项目范围自动保存。个人偏好通常使用 global；项目约定通常使用 current。

子 Agent 暂不接入记忆能力。子 Run 不获得记忆工具，也不自动加载记忆索引。Runtime 同时拒绝子 Run 的直接模型读取入口。定时任务和渠道输入仍不开放记忆写入。

| 模式 | 模型读取 | 自动保存 | 用户明确要求保存 |
| --- | --- | --- | --- |
| off（关闭） | 系统关闭 | 系统关闭 | 系统使用当前 Run 的普通审批路径 |
| read（只读） | 系统开启 | 系统关闭 | 系统使用当前 Run 的普通审批路径 |
| auto（自动） | 系统开启 | 系统在当前 Run 中保存和整理 | 系统使用相同的自动记忆写入路径 |

新范围默认使用 auto。自动模式按目标范围判断。当前项目只读时，全局 auto 范围仍可自动记录个人偏好。read 与 auto 之间切换不会撤销已有读取；切换 off 会推进隐私撤销版本。用户始终可以在设置页查看和编辑笔记。

自动流程可以更新用户以前写过的笔记。`userOwned` 只记录版本的编辑来源，不再锁住整篇笔记。模型负责区分已知事实、用户决定、提议和假设。模型应保留有助于未来任务的信息，并跳过没有后续价值的临时内容。四种类型仍是 `user`、`feedback`、`project`、`reference`；类型只用于组织笔记。

Runtime 自动记录本次 Run 的用户消息和最近普通工具结果，最多记录 16 个来源。来源记录只用于追踪，不能证明正文每句话都正确。模型不填写数据库 Item ID。服务不再因为来源来自其他会话、早于开关开启时间、未通过旧的资格检查或在准备期间发生变化，就拒绝整篇笔记。旧笔记可以参与合并和更正。Assistant 自述不会被记录为已经核实的工具观察。

删除聊天、修订消息、重写 Run 和 Checkpoint 回退只更新聊天来源记录，已经保存的笔记继续存在。用户明确遗忘某篇笔记后，系统保留最小来源抑制记录，防止相同旧来源再次自动生成它。

## 工具与版本

| 工具 | 模型使用方式 |
| --- | --- |
| `memory_search` | 模型按词搜索，或省略 query 分页列出笔记；模型只在恢复或检查归档时使用 `includeArchived: true` |
| `memory_read` | 模型读取索引、主题笔记或指定历史版本；后续页固定 revision，并使用 nextOffset |
| `memory_edit` | 模型创建、更新或归档笔记；Runtime 自动取得来源和更新版本 |

模型侧 `memory_edit` 不再暴露 `sourceItemIds`、`userRequested` 和 `expectedRevision`。读取开启时，模型更新已有笔记前需要在本次 Run 读取它。Runtime 从已经完成的读取或写入记录取得 CAS 基准。off 模式下，用户明确要求替换已有笔记时，Runtime 在内部取得当前版本，再进入普通审批路径；旧正文不会发送给模型。模型创建不存在的路径时，Runtime 使用版本 0。并发修改目标笔记仍会返回版本冲突；模型可以重新读取后继续。不同笔记的写入不会因为同一范围的 generation 变化而互相拒绝。

标题和类型省略时，Runtime 保留现有值；新笔记采用路径标题和默认类型。摘要可以省略。已有笔记保留原摘要，新笔记使用正文首个非空行作为默认摘要。完全相同的正文、标题、摘要与类型不会增加版本。

模型在 auto 范围的普通保存、更正和归档使用同一授权路径，不额外发起逐项审批。read/off 范围的明确保存继续使用 Run 的 manual/auto_review/full_access 规则。模型工具不能改变范围模式。Desktop 编辑接口仍使用显式 `expectedRevision`，以保护用户草稿。待审批操作在相同工具契约下可以重启恢复；工具契约变化时，Runtime 继续拒绝直接执行旧调用。

单篇笔记上限是 65,536 字符。每次读取最多 16,384 字符。模型结果另有 48 KiB 序列化预算。正文超出结果预算时，工具按完整字符缩短本页，并把 `nextOffset` 指向实际返回正文后的第一个字符。Unicode 和 JSON 转义都计入预算。模型继续调用 `memory_read`，结果不附带无法读取记忆的通用回读指针。工具错误返回模型，模型可以修正和继续处理任务。

## 模型结果与内部记录

完整存储结果、Desktop 详情和模型视图使用不同投影。模型只获得以下信息：

| 结果 | 模型需要的字段 |
| --- | --- |
| 搜索成功 | `outcome`、笔记的 `scope/path/revision/summary`；归档记录另有 `archived: true`；后续页另有 `nextCursor`，候选达到上限时另有 `searchLimited: true` |
| 读取成功 | `outcome`、`scope/path/revision/content`；主题笔记另有可编辑的 `title/summary/kind`；归档笔记另有 `archived: true`；剩余正文另有 `nextOffset` |
| 编辑成功 | `outcome/code/path/revision`；彻底删除结果不提供用于后续写入的版本 |
| 错误 | `outcome/code/summary`；完整结果为 true 的副作用或未知状态标记继续保留 |

`scope` 使用 `current/global`。模型结果不包含 `scopeId`、内部 UUID、来源审计、时间戳、`currentRevision`、历史版本列表、`userOwned`、`epochs`、重复的工具名与契约版本。结果也不携带无关的空数组、null、默认 false 和重复包装。

ContextBuilder 从 SQLite 的原始读取记录取得隐私撤销版本。该信息只保存在私有上下文元数据中，不进入 Provider 的工具正文。冻结分叉沿原始 Item 查询。既有会话重建与摘要来源视图使用相同的字段精简。

## 归档、遗忘与撤销

模型的 `memory_edit(action=delete)` 会归档笔记，并返回 `memory_archived`。归档会保留正文和历史版本，预留原路径，并从默认搜索与索引中移除笔记。设置页仍显示归档笔记和“已归档”状态。用户可以直接恢复，也可以查看历史或彻底删除。模型可以通过 `memory_search(includeArchived=true)` 找到归档笔记，读取后重新写入原路径恢复。

设置页的“删除笔记”会彻底遗忘正文与全部版本，并推进目标范围的隐私撤销版本。关闭记忆也会推进该版本。Runtime 在快照保存、重试、请求准入和最终化时检查撤销。系统取消相关在途请求，忽略取消的迟到响应也不能发布。后续请求从合法事实重建。冻结分叉中的旧载荷会同步拒绝使用，并由有界维护任务分批擦除。

普通保存、归档和恢复只增加笔记版本及索引 generation。它们不推进隐私撤销版本，也不取消已经使用旧读取快照的其他 Run。发布事务复核目标笔记 CAS、当前模式、显式隐私撤销与取消状态，并从最新笔记集合生成索引。SQLite 事务同时提交业务结果与 `memory.changed` Event/Outbox。

待审批工具恢复继续读取原始 Step 的工具契约和 Run 的固定权限，不依赖已撤销的请求正文。Context Usage 只查询已保存预算和 Provider 用量，不读取已撤销正文。

read/off 模式的明确替换使用 Desktop 已有的文件变更审批与预览。off 模式的预览只显示新内容，不包含旧正文。系统在内部持久保存审批前的目标版本和读取模式。用户切换模式后，原待审批操作仍等待原决定。目标版本已经变化时，系统使旧审批失效并返回工具冲突，Run 继续处理后续任务；系统不会创建执行 Intent，也不会覆盖新内容。

遗忘保留原始聊天。系统不能追回已经发送给 Provider 的资料，也不能删除用户另存的导出、备份或自然语言复述。系统不承诺磁盘块安全擦除。

## 搜索、维护与 Desktop

搜索使用 FTS5 unicode61、可用时的 trigram、短词 LIKE 和 RapidFuzz 重排。每个候选源最多读取 500 条。查询分页覆盖有界候选集。命中上限时，工具返回 searchLimited。搜索不保证语义改写召回；模型可以缩小查询，或省略 query 分页遍历笔记。

ContextBuilder 只自动注入短索引，正文按需读取。索引最多使用可用输入预算的 5%，且不超过 2,000 个估算 token。系统优先显示当前项目索引，并保留继续读取提示。系统不把整库正文放入每个请求。

`StorageMaintenance` 由现有 Supervisor 管理。它只清理撤销载荷、失效文件和 Blob，不调用模型，也不产生新记忆。启动时，快照外置流程跳过已经撤销的记录，避免把清空的载荷重新写成 Blob。真实撤销仍按原有流程清理，孤立文件保留一小时宽限，准备中的文件受到保护。关闭仍由资源注册表统一取消和等待。

记忆页复用范围、模式、文件列表、编辑区域、来源与版本、删除确认及 Markdown 导出。用户编辑时，页面不切换范围或覆盖草稿。冲突会保留草稿。归档恢复和彻底遗忘不增加设置开关。Main 校验 `memory/changed` 通知，页面据此刷新，并在恢复可见或获得焦点时刷新。页面不定时轮询任务。

## 备份与契约

Markdown 导出只包含生效笔记。Main 分页写入临时文件，并核对同一 generation 与递增游标，全部成功后才原子发布。完整 ZIP 备份位于“运行时 → 本地数据”，同时保存归档笔记和历史。

完整备份格式是 `eidos-data-backup-v2`。恢复接受 schema v40/v41/v42/v43，逐级升级后导入一个不存在的新目录，并把记忆模式设为 read。恢复检查归档路径、重复成员、符号链接、体积、SQLite 完整性、记忆引用和 Blob，修复文件时间元数据。备份不包含 Workspace 或模型凭据配置。ZIP 未加密，旧备份可能恢复备份之后被遗忘的资料。

Python 严格 DTO 生成 Desktop 类型与 JSON Schema。两端共同验证 `protocol/fixtures/memory-v2.json`，模型结果另用 `memory-tool-model-v1.json`。运行方法见[记忆专题](../../development/README.md#记忆系统)。真实 Provider 的长期记忆质量仍需独立评测，脚本模型测试不能替代该证据。
