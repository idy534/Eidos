# 当前记忆系统

读者可以在[记忆架构专题](../../architecture/memory.md)查看读取、发布和撤销的结构图与时序图，并在[Harness 组成总览](../../architecture/harness-overview.md)比较长期记忆、压缩摘要与请求快照的职责。

Eidos 使用 `MEMORY.md` 索引和主题 Markdown 笔记。前台模型在当前 Run 中保存记忆。Run 会等待保存结果。系统没有闲置后生成记忆、后台模型整理、候选确认或历史回填流程。

记忆是带来源的历史资料。当前用户指令和已经核实的现状优先。记忆不授予权限，也不改变审批模式。

## 数据与升级

`state.sqlite` schema v42 是唯一业务事实来源。它保存作用域、模式、当前版本、来源证据、操作结果、抑制记录和撤销版本。正文是数据目录 `memory/scopes/<scope UUID>/revisions/<revision UUID>.md` 下的不可变私有文件。用户和模型使用相对笔记路径访问它们，例如 `feedback_testing.md`。SQLite 负责把这个路径映射到有效版本。孤立文件不能成为记忆。

`MEMORY.md` 是服务端按有效笔记的路径和摘要生成的索引。系统不维护另一份 `memory_summary.md`。模型不能改写索引。索引最多 200 行、约 24 KiB；索引末尾会提示继续搜索和分页读取。

本次升级按用户要求直接清空旧记忆。v39→v40 在同一 SQLite 事务中删除旧记忆条目、版本、证据、任务、预算、使用记录及旧索引，撤销旧上下文，并清除旧记忆工具、审批与相关 Hook 载荷。迁移失败会回滚 schema 和版本。新的 Runtime 第一次打开记忆服务时会删除旧 `memory/`、`memories/` 和 `memories.sqlite`（含 WAL/SHM），同时丢弃可重建的 Hook transcript 缓存，再创建新文件目录。持久标记保证文件删除失败后可以重试；成功后不会再次清空新笔记。

升级保留聊天、项目、执行记录和其他配置。旧的使用/自动开关只映射为新的 off/read/auto 模式，避免升级扩大权限。系统不转换旧记忆内容，不支持旧记忆接口和旧备份格式。旧版本 Runtime 不能打开 v40 数据。

v40→v41 在事务中更新来源撤销触发器，并撤销旧版可能遗漏的历史自动版本上下文。该升级保留现有笔记、用户控制版本和模式。迁移失败会回滚触发器、撤销版本和 schema 版本。

v41→v42 移除会话级临时记忆模式、`memory/temporary` 接口和 `memory_sources.temporary` 字段。原临时会话开始按全局/项目模式使用记忆。迁移保留聊天、已有笔记和模式设置，并使原临时来源保持失效；新消息可以按当前模式提供证据。升级会推进原临时会话的使用版本，并保留其他来源撤销规则。失败时，系统回滚字段和 schema 版本。

目录和文件继续使用私有权限、目录 FD、`O_NOFOLLOW`、普通文件与硬链接检查、fsync 和原子发布。服务在发布前准备文件，在事务中重新检查来源版本、目标版本 CAS、作用域 generation、撤销版本和取消状态。读取会检查保存的大小与 mtime，正文缺失或被修改时拒绝使用。这项检查不能识别主动保留大小与 mtime 的篡改。

## 范围、模式与来源

全局与项目范围由服务端的项目身份决定。Projectless 的当前范围是全局。项目 Worktree 共享所属项目的记忆。Child 沿 Root 的范围只读访问，不能写入记忆。定时任务和渠道输入不能成为自动记忆证据，工具目录也不开放写入。

| 模式 | 模型读取 | 自动保存 | 用户明确要求保存 |
| --- | --- | --- | --- |
| off（关闭） | 关闭 | 关闭 | 仍走当前 Run 的明确保存授权 |
| read（只读） | 开启 | 关闭 | 仍可明确保存和更正 |
| auto（自动） | 开启 | 在当前 Run 中执行 | 仍可明确保存和更正 |

新范围默认使用 auto。升级已有范围时保留原权限意图。模式只控制模型的使用与自动保存；用户仍可以在设置页查看和编辑笔记。系统不再提供会话级临时记忆模式。

模型应该保存能减少用户重复说明、能帮助后续相关任务的信息。主题笔记可以保留一组有关的条件、经验和决定，不要求把每句话拆成独立条目。模型应该跳过临时要求、重复信息、假设和没有后续价值的内容。四种组织类型是 `user`、`feedback`、`project`、`reference`；类型不构成允许保存内容的白名单。

Runtime 会从真实用户消息或成功的普通工具结果解析证据类别。Assistant 自述、记忆工具输出、失败或未完成工具、其他会话、已经修订或删除的来源及被抑制的来源不能作为证据。自动保存只使用本范围开启后的资料，并在权限检查和 Durable Intent 前捕获具体 Item 版本。发布事务不能用重新捕获版本接受中途被修改的来源。

用户从设置页保存的内容，以及模型按用户明确要求保存的版本，属于用户控制版本。自动流程不能覆盖它们。模型必须先读取目标笔记，再使用当前 revision 更正。相同操作 ID 和相同请求会返回原结果；相同 ID 与不同请求会被拒绝。完全相同且所有权不变的正文、标题、摘要与类型不会增加版本。

## 工具与上下文

| 工具 | 行为 |
| --- | --- |
| `memory_search` | 按词检索当前可用范围，返回笔记元数据和下一页 cursor |
| `memory_read` | 按相对路径读取索引或指定版本的笔记，支持 offset/nextOffset 分页 |
| `memory_edit` | 创建、整篇更新或删除主题笔记；写入使用 expectedRevision CAS |

单篇笔记上限是 65,536 字符。每次读取最多 16,384 字符。分页读取必须固定第一页返回的 revision。系统没有每 Run 三次读取或累计 16 KiB 的旧配额。工具错误返回模型，模型可以修正参数和继续处理任务。

`memory_edit.userRequested` 区分明确保存请求和自动保存。用户明确设定未来行为也可以表达保存请求。删除必须来自明确请求。自动保存仅限当前范围的 auto 模式。两条写入路径都保留参数校验、来源检查、Durable Intent、取消、CAS 和结果校验；明确请求继续遵循 Run 的 manual/auto_review/full_access 规则。系统不会为记忆保存另外发起一次模型审核。

FTS5 unicode61、可用时的 trigram 和短词 LIKE 检索提供候选，RapidFuzz 参与重排。查询文本不直接作为可执行的 FTS 表达式。每个候选源最多读取 500 条，查询分页覆盖该有界候选集。命中候选上限时，工具返回 searchLimited，页面提示细化关键词。搜索不保证语义改写召回；模型可以缩小查询，或按文件列表分页访问全部有效笔记。

ContextBuilder 只自动注入短索引，正文按需读取。投影优先显示当前项目索引，并为截断提示保留预算。索引投影最多使用可用输入预算的 5%，且不超过 2,000 个估算 token。成本进入 ContextBudget。投影和读取都绑定作用域 privacy epoch 与 Root 会话 use epoch。系统不会把整库正文放进每个请求。

## 撤销、遗忘与维护

模式变化、来源修订、Run 重写、Session 删除和 Checkpoint 回退继续通过持久事实撤销相应记忆。非用户控制版本会被隔离。用户控制的独立版本保留。删除笔记会遗忘全部正文版本，保留最小来源抑制记录，防止相同旧来源再次自动生成。

来源撤销按具体历史版本的所有权判断。即使当前笔记已经由用户编辑，旧自动版本的来源失效后，系统仍会撤销其读取结果和上下文，并取消在途请求。当前用户控制版本继续保留。

Runtime 在快照保存、读取、重试、最终化和模型请求准入时检查撤销版本。源资料失效或用户撤销会取消相应请求。忽略取消的迟到响应也不会发布。新请求会从合法事实重建。历史工具的写入参数与读取结果一起被撤销。分叉会话读取冻结工具结果时也会复核原始读取记录；后台存储清理会分批擦除被冻结的旧载荷。

待审批、待输入或等待子 Agent 的工具恢复只读取原始 Step 的工具契约和 Run 的固定权限。恢复不读取已撤销的模型请求快照。旧正文即使已经清理，任务仍能继续按原有审批和工具契约完成恢复。

Context Usage 继续只查询已经保存的预算和 Provider 用量。统计查询不读取已撤销正文。

遗忘保留原始聊天。它不能追回已经发送给 Provider 的资料，也不能删除用户保存的导出、备份或自然语言复述。系统不承诺磁盘块的安全擦除。

`StorageMaintenance` 由现有 Supervisor 管理。它只做撤销载荷清理、文件与 Blob 回收、已有存储维护。它不调用模型，不整理对话，也不产生新记忆。孤立文件有一小时宽限，单次最多扫描十万项，准备中的文件受到保护。关闭仍由资源注册表统一取消和等待。

业务变化和 `memory.changed` Event/Outbox 在同一事务提交。Main 向 Renderer 投递严格校验的 `memory/changed`，仅包含 scopeId 和 generation。页面据此刷新，窗口恢复可见或获得焦点时也刷新。搜索去抖 250 毫秒。页面不会定时轮询任务。

## Desktop 与备份

记忆页只提供范围、单一模式选择、文件列表/搜索、笔记预览与编辑、新建、删除和 Markdown 导出。来源和版本位于正文下方的详情区。用户编辑期间，页面不会切换范围或覆盖草稿。保存冲突会保留草稿。历史版本只读，编辑和删除作用于当前版本。

设置页只把已经保存的会话 ID 传给记忆接口。新聊天草稿尚未写入 SQLite，页面会使用全局记忆范围，不会把 `draft-*` ID 作为真实会话发送。用户进入已经保存的会话后，页面继续按该会话的项目身份选择当前范围。

Markdown 导出按页读取整个所选范围。Main 逐页写入临时文件，并核对同一 generation 与递增游标。全部成功后才原子发布目标文件；失败会移除临时文件。完整 ZIP 备份位于“运行时 → 本地数据”，路径由 Main 原生保存对话框提供。Renderer 不能自由指定备份路径。

完整备份格式是 `eidos-data-backup-v2`。它一致保存当前 SQLite、引用的记忆文件、执行 Blob 和 Agent 定义。备份不包含 Workspace 和模型凭据配置。ZIP 含私有聊天，也可能含 MCP 环境配置，且未加密。

恢复接受当前格式和 schema v40/v41/v42，并导入一个不存在的新目录。恢复会检查归档路径、重复成员、符号链接、体积、SQLite 完整性、记忆引用与 Blob 内容；它会修复文件时间元数据，把 v40/v41 升级为 v42，并把记忆模式设为 read。旧格式直接拒绝。恢复不会合并运行中的数据，也不能知道备份之后发生的遗忘。

Python 严格 DTO 是共享契约来源。生成器维护 TypeScript 类型和 JSON Schema，Main 使用 AJV 校验两端白名单。两端共同验证 `protocol/fixtures/memory-v2.json`。运行方法和人工验收见[记忆专题](../../development/README.md#记忆系统)。真实 Provider 的长期记忆质量和真实桌面交互仍需单独验收，定向脚本模型测试不能代替这些证据。
