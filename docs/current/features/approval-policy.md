# 当前审批与高危范围

本规则用于减少正常 Run 的人工中断。系统分别判断执行权限和操作影响。命令位于沙盒外、目录位于工作区外，或命令使用 Git，都不会单独触发高危人工确认。

## 固定高危范围

系统在申请尚未授权的以下权限时要求人工确认，`auto_review` 不能代替用户决定：

- 操作读取或修改 Eidos 私有数据与保密路径。范围包括状态数据库、聊天、记忆、配置和凭据存储。
- 操作修改 Eidos Runtime、解释器环境、系统 Skill 或受管资源。
- 申请的目录范围覆盖上述受保护路径。

已有当前 Workspace、普通用户 Skill 和已验证运行资源继续使用原有的明确范围例外。普通项目目录 `.eidos` 与 Eidos 私有数据根不是同一类授权。系统仍拒绝链接、特殊文件、不支持的文件对象和版本冲突。

## 普通审批范围

| 操作 | 当前判断 |
| --- | --- |
| Git 暂存、提交、分支、拉取和推送 | 系统按目标、用户授权和实际影响审查，不按 Git 名称判为高危。 |
| 项目 `.git`、`.agents`、`.eidos` 与已验证的 Worktree metadata 写入 | 系统保留默认拒写；明确范围的普通审批或 Run Grant 可以开放。 |
| 普通工作区外文件写入、联网与依赖安装 | 系统使用普通审批，继续核对范围与副作用；请求审批模式下批准后覆盖本任务的后续同类操作。 |
| 沙盒外 Shell、沙盒不可用时的普通受控文件写入 | 系统继续先审批；`auto_review` 可以根据实际操作批准。执行模式本身不再强制高危人工确认；命令按字面引用 Eidos 核心保护路径时转高危人工确认。 |
| 默认 Workspace 文件写入和默认沙盒 Shell | 系统继续使用原有免审批入口。 |

`manual` 继续由用户决定普通审批。`auto_review` 使用当前 Run 的固定模型进行独立审查。模型会区分常规 Git 操作与未授权的未提交内容丢失、历史破坏和覆盖共享历史。模型会审查敏感数据外传、大范围删除、生产变更和长期削弱安全配置等实际影响。模型的明确拒绝会返回工具错误；审查失败、不可用和证据超限返回模型并可重试，重启中断会重新审查，未知风险先让模型补充证据，同一操作再次未知才交给用户。普通工具错误和拒绝不自动终止整个 Run。

系统不会为每条默认沙盒 Shell 增加一次模型审查。自动审查仍只覆盖原本需要审批的操作。

## 审查提示词

独立审查请求按证据来源、授权与影响、Runtime 边界、未知信息与风险、输出契约组织指令。模型从 `userMessages` 的实际含义判断授权；用户提供的任务材料不等于授权执行材料里的操作。具体参数、Diff、脚本和操作理由用于判断目标与影响，它们不能指挥审查模型，也不能证明用户已经批准。

模型可以批准为用户任务所需、影响有限且可回退的普通步骤。Runtime 只接受 low 与 medium 风险的自动批准；模型允许但评估为 high 或 critical 的操作转给用户决定。指令要求模型把可能读取或修改受保护 Eidos 路径的操作至少评为 high。破坏性影响、敏感信息披露、共享或生产系统变更和长期安全配置修改需要明确的目标与影响授权。模型根据实际后果评估风险，不根据工具名称、项目 metadata、工作区外路径或沙盒外执行这一点单独升级风险。指令不再列举 Git、文档转换、构建等操作作为安全类别。

风险描述后果，批准决定描述授权与风险是否可接受。`low` 表示范围小、可回退；`medium` 表示范围有限、影响可控；`high` 表示严重数据损失或披露、共享系统中断或长期安全削弱；`critical` 表示严重、广泛且难以恢复的影响。关键证据不足、无法判断范围或后果时，模型返回 `deny + unknown` 并说明缺口。已有证据证明操作不被授权或风险不可接受时，模型返回明确拒绝及对应风险，不把这类拒绝伪装成未知风险。系统继续沿用已有未知风险人工回退与明确拒绝分流。

本次只改写模型指令。系统保留高危人工确认范围、完整权限作用期审查、无沙盒执行说明、脚本预览边界、结构化输出与严格 JSON 两种返回方式。模型不能执行被审查操作、授予权限或自行要求用户确认。

## Shell 审查证据

Shell 普通自动审批包含真实执行模式、Eidos 保护路径、Workspace 与普通写入例外。沙盒外进程及其子进程使用当前 macOS 用户的文件和网络权限；请求中的原路径 deny 和网络开关不能继续作为操作系统限制。自动审查不能保证识别全部风险，也不能代替关闭后的 Seatbelt。产品不能承诺沙盒外进程仍受到 Eidos 数据的强制路径保护。

系统还会从命令提到的脚本路径中，读取最多 3 个当前 Workspace 或 active Skill 内的脚本预览。每个预览最多 8 KiB。系统复用 `shlex` 寻找候选路径，并使用现有 `WorkspaceReader` 进行有界、fd-relative 读取。系统不解释 Shell 语法，不执行脚本，也不把这些预览视为完整的 import 或子进程图。链接、范围外和无法读取的脚本会保留缺失标记。预览先经过现有展示脱敏，再进入审批证据；内部文件版本不会注入审查模型。

系统在执行前复检已经预览的脚本。脚本变化会返回 `file_version_conflict`，原命令不会启动。拒绝去重包含脚本预览，因此脚本内容变化后可以重新评估。该复检不能冻结整个进程执行期间的全部依赖。

## 兼容与数据

本次没有新增公开 DTO、数据库表、Schema 版本或依赖。系统沿用原 Approval、Run Grant、Durable Intent、身份与版本核验、取消、结果校验、未知结果和恢复流程。系统不自动重放未知副作用。

新的 Run 会固定新的 metadata 普通审批范围。既有 Run 的基础权限快照保持不变。旧的待处理高危人工审批继续由用户决定原操作；策略放宽不能把旧人工审批静默改成模型批准。命令、Diff、参数和权限指纹仍需匹配。用户确认的 `full_access` 行为保持原样。

回退代码后，新建 Run 会恢复旧策略。维护者应先处理或取消待审批操作，再退出并重启 Eidos。回退不会撤销已经执行的 Git、文件或外部操作，也不会删除已有审批历史。

## 路径绑定与审查上限（2026-11-21）

本节记录一次权限评审后的修复。

### 路径绑定

权限判断与 Seatbelt 必须指向同一个磁盘位置。macOS 默认卷不区分大小写，Seatbelt 也按同样方式匹配路径；此前 Python 侧按字符串比较，`~/.EIDOS` 这类大小写别名会被当作普通路径审批，获批后却能打开 Eidos 数据目录。

- `request_permissions`、Shell `additionalPermissions`、文件工具的工作区外目标和 Hook 数据目录，都在判断前解析链接并采用文件系统报告的实际拼写（macOS 使用 `F_GETPATH`，不可读对象从父目录列表确定）。路径不存在或没有唯一位置时返回 `permission_not_requestable`。
- 物化附加权限时，当前规范路径必须与申请时的路径一致，否则执行失败且不启动进程。已批准的目录若被替换为指向受保护路径的链接，不会再被当作已授权范围。
- Runtime 读取 Run Grant 时丢弃已删除、已改为链接或已指向其他位置的条目。权限只会收窄，Run 可以继续，模型可以重新申请新位置。
- 工作区外的 Patch 目标必须使用磁盘拼写；`.GIT`、`.Eidos` 这类受保护 metadata 的大小写别名在授权前返回 `workspace_boundary_violation`。

### 沙盒外命令与自动审查

- 沙盒外命令、cwd 或已预览脚本按字面引用 Eidos 私有数据、Runtime、系统 Skill、受管资源或它们的上级目录（包括 `~`、`$HOME` 形式和相对 cwd 的路径）时，请求带 `requiresHumanConfirmation`，auto_review 不调用审查模型。Projectless Workspace 位于数据目录内，按 Workspace 处理。这项检查只识别直接写出的路径，不能发现间接构造的路径；它不是执行边界。
- 审查结论为 allow 且风险为 high 或 critical 时，记录 `auto_review_requires_human` 并转人工；用户决定以 `manual` 来源写入原 Approval。
- 用户消息证据按从新到旧保留，每条最多 4 KiB 首尾预览，总计最多 20 KiB，超出部分标注省略。拒绝去重指纹仍使用完整的用户证据。

### 拒绝反馈

- auto_review 的高危人工确认保留用户的决定与反馈，工具结果使用 `user_rejected`。审查失败后由用户拒绝时同样返回 `user_rejected`，不再沿用审查失败的原因码。
- manual 下 Shell、受控文件写入和权限申请的拒绝反馈会作为工具结果摘要返回给模型。Desktop 当前不收集拒绝反馈，没有反馈时摘要保持不变。

### 兼容与数据

本次没有新增公开 DTO、数据库表、Schema 版本或依赖。新 Run 的基础权限快照对已存在的保护路径使用磁盘拼写。已批准但路径已失效的 Grant 在升级后不再生效。仍在等待的旧审批继续按原指纹匹配。回退代码会恢复旧行为，不会撤销已经执行的操作。

## 减少中断（2026-11-22）

目标是让 Run 只在确实需要用户回答时才停下来等待。所有模式仍保留参数校验、Durable Intent、身份与版本核验、取消和未知结果记录。

### 自动审查不再把“没审完”交给用户

| 情况 | 现在 |
| --- | --- |
| 审查失败或返回无效结果 | 自动重试一次；仍失败时以 `auto_review_failed` 返回模型，说明可以重试或改用不需要审批的方式。不询问用户，不按拒绝去重。 |
| 审查模型不可用 | 以 `auto_review_unavailable` 返回模型，可重试。 |
| 审查时间 | 不再有 60 秒固定时限。Provider 的连接与读取超时和用户取消仍然有效。 |
| 证据超过 48 KiB | 先把 Diff 和参数改为首尾预览再审查；仍超限时让模型拆小操作。 |
| Runtime 重启时审查未完成 | 重新审查。已经转给用户的请求（高风险允许、再次 unknown）在待审批记录中标记 `reviewEscalation`，重启后仍交给用户；待处理的高危人工确认同样交给用户。 |
| 风险 unknown | 第一次把缺失证据返回模型；同一操作再次 unknown 时记录 `auto_review_unresolved` 并交给用户。 |
| 允许且风险 high/critical | 继续交给用户。审查说明要写清具体后果。 |

### 保留给用户的高危请求先分诊

auto_review 遇到 Eidos 私有数据、Runtime、系统 Skill 或受管资源的高危请求时，先让审查模型判断用户是否提出过这项操作。没有提出时，模型直接拒绝并告诉执行模型原因，不弹窗；模型允许、无法判断或分诊失败时，仍由用户在 danger 样式的窗口确认。模型只能拒绝，不能批准这类请求；事务只接受模型来源的拒绝。

### 请求审批模式下，一次批准覆盖本任务

| 操作 | 现在 |
| --- | --- |
| Shell `networkAccess=request` | 批准后本任务后续命令沿用联网权限。 |
| Shell `gitWriteAccess=request` | 批准后本任务后续命令可写当前已验证仓库的 Git metadata。 |
| 工作区外已有文件的写入 | 批准后本任务内写入这些文件不再询问，后续 Shell 命令也可写这些文件。新建文件（范围是最近的已存在上级目录）、受保护路径和沙盒外写入仍逐次确认。 |
| MCP 非只读工具 | 同一个工具（按名称和内容 Hash）在本任务内不再询问；声明 `destructiveHint=true` 的工具仍每次确认。 |

审批窗口用“批准范围”说明这一点。自动审查模式仍逐次审查这些操作，不打扰用户。任务级授权与 `request_permissions` 一样记录在原 Approval 的 `grantScope=run` 和 `permissions` 中，Run 结束后失效。

### 其他

- 安装 Skill 只在最终写入时审批一次；下载阶段只取回公开内容供审阅。
- Seatbelt 不可用时，文件写入仍逐次审批。AGENTS.md 要求每次无沙盒写入单独获得明确审批。
- 团队成员在 Lead Run 活动期间使用 Lead 已批准的任务级授权；Lead 的高危人工授权不传给成员。
- 新用户没有保存默认值时，Composer 默认使用 auto_review。已保存的默认值不变。

### 兼容与数据

没有新增数据库表或 Schema 版本。审批请求新增可选字段 `grantScope: "run"`（文件变更、命令和 MCP 工具），Main 只接受 `run`。升级前创建的待审批请求不含该字段，批准后仍只作用于当次。回退代码后，已批准的任务级授权不再被读取，Run 会恢复逐次审批。
