# 系统提示词与上下文

Eidos 使用 macOS 桌面通用助手身份。系统支持聊天、研究、文件和编码任务。工作区与工具提供资源，不替用户建立目标。生产规则使用英文，主要文本位于 `model/prompts.py`，组装入口是 `InstructionResolver.resolve`。

## 内容与来源

| 内容 | 当前职责 | 来源 |
| --- | --- | --- |
| 系统规则 | 系统定义身份、指令顺序、诚信、任务处理、工具策略、验证、交付和恢复要求。 | `model/prompts.py` |
| 动态规则 | Runtime 根据实际状态生成工作模式、权限与记忆读写要求。 | `model/instructions.py` |
| 工具定义 | 当前可用工具直接提供名称、用途、参数和操作限制。 | `tools/`、已启用的扩展 |
| Skill 目录 | 系统提供本轮可用的名称、描述和加载入口。 | 冻结的 Skill Catalog |
| 来源上下文 | 系统分别提供项目规则、所选 Skill、用户偏好、记忆、环境、仓库资料和任务状态。 | `ContextBuilder` 与现有持久事实 |
| 用户输入 | 系统保留真实用户原文及其关联附件。 | Session Item 与输入引用快照 |
| 执行历史 | 系统保留助手回复、工具调用、结果及必要的子任务证据。 | SQLite 历史与请求快照 |

`InstructionLayer` 延用既有的持久化角色分类，旧快照保持可读；其低层指导由 `context_layers` 单独取得，不合入核心规则。这些分类不是 Provider 用户消息。`ContextBuilder` 把项目规则、所选 Skill 和偏好投影成独立 `context` Item，并保留来源。记忆索引和环境也使用该 Item 类型。真实用户文本不因翻译、渠道来源或自动任务来源而被改写；来源约束由单独区域提供。用户选择的附件仍与其原始输入关联。

`SourceContext` 使用严格 Pydantic 模型表达来源、用途和正文。模型适配器把文本发送为带来源的 `eidos_context` 区域，并转义正文中的边界字符。项目规则、Skill 和偏好属于有范围的指导；记忆、摘要和工具历史属于证据。系统核心明确说明：这些区域不是新的人类消息或系统规则更新，也不能授予权限。

Provider 没有统一的上下文角色。Pydantic AI 路径使用 SDK 的 `SystemPromptPart` 承载该区域；Responses 路径使用 developer 消息。系统没有把它们声明成新的 Runtime 政策。文本标记不能提供模型层的绝对隔离，实际权限仍由 Runtime 执行。

兼容回放缺少完整推理信息或跨 API 的历史响应时，适配器保留有来源的文本证据，不再把该文本伪装成用户新要求。SDK 与 Provider 的图片接口仍需要消息附件。在这些兼容分支中，已保存图片继续以明确标记的历史附件发送，其文字证据保持独立。系统不丢弃图片，也不重新读取原路径。普通有效工具回放继续保留原生调用与结果关系。

## 工具与 Skill

当前 Run 中已配置、可用且符合角色范围的工具从首轮直接提供。项目与无项目主 Run 使用相同的可用性原则。内置 automation 与已启用 MCP 工具不再延后展示。系统不注册 `tool_search`，也不要求搜索后才能调用工具。工具可用不代表操作已获准；参数、审批、Sandbox、Durable Intent、结果核验与未知结果记录继续生效。

旧的激活记录、快照字段和结果投影继续保留读取兼容。新请求的正常工具集合没有延后项。历史 Step 中原本不可用的调用不能因新版直接展示而被自动重放。未知、禁用和未授权工具也不会因为移除搜索入口而进入目录。

Skill 目录使用 `available_skills` 区域。每项包含唯一名称、description 和 `skill_read` 加载入口。名称对应 `qualifiedId`。模型使用 Skill 时读取主说明，再按需要通过 `skill_read_resource` 读取相对文本资源。目录不注入全部正文或文件树。同一 Turn 的目录与所选内容仍使用既有快照，文件监听不能静默替换它们。

Skill 资源访问继续沿用现有激活、Lease 和身份检查。移除工具搜索不开放所有 Skill 文件，也不提供写权限。二进制模板和图片继续通过已有文件、Shell 或图片工具处理。

## 环境、记忆与恢复

项目和无项目 Run 都提供实际工作目录、附加目录、平台、宿主 Shell 信息、当地日期与时区。日期和时区复用现有本地时间解析。工作区版本仍是 Runtime 内部事实，不加入环境提示。需要精确时间的任务应取得新鲜时间，已持久化请求的重试仍复用原快照。

读取开启时，主 Run 从首轮提供当前范围的短记忆索引。正文仍按需要读取，既有索引预算、范围、模式和子 Agent 隔离保持不变。记忆的私有撤销元数据继续附在上下文中，不发送给 Provider。关闭、遗忘、请求准入、重试与迟到响应仍经过原有检查。

恢复投影识别新的上下文 Item，并保留项目与 Skill 指导、来源约束、记忆撤销记录和连续性信息。摘要仍是历史资料，不能变成当前用户决定。未知副作用不构成新的核验门，也不会被自动重放。

## 维护与验证

稳定原则由核心维护，动态值由 Runtime 生成，参数细节由工具契约维护，专题流程由 Skill 提供。系统不强制公开三段式任务流程，也不要求用户给自然输入添加特殊标签。维护者不以提示词字数或 Token 减少比例判断成功。

本批修改没有增加依赖、公开协议或数据库迁移。系统沿用现有 Model API、状态权威、快照和恢复机制。旧请求保持原样，新版只影响新构建的请求。回退时应还原本批源码与文档并重新载入 Runtime，不应删除用户记忆或历史快照。

定向验证覆盖首轮直接读写、Skill 与资源读取、记忆模式、来源投影、两条模型路径、图片保留、取消和请求快照。真实服务证据与尚未验证的范围见[当前限制](../limitations.md#上下文来源与直接工具2026-11-01)。
