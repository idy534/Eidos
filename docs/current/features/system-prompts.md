# 系统提示词与上下文

Eidos 使用 macOS 桌面通用助手身份。系统支持聊天、研究、文件和编码任务。工作区与工具提供资源，用户请求确定目标。生产规则使用英文，主要文本位于 `model/prompts.py`，组装入口是 `InstructionResolver.resolve` 与 `ContextBuilder`。

## 内容与来源

| 区域 | 当前职责 | 来源 |
| --- | --- | --- |
| 系统提示词 | 系统提供身份、指令顺序、安全与权限原则、任务流程、工具和记忆的使用规则。工作区是 Git 仓库时追加 `# Git` 安全规则。Runtime 提供实际工作模式和 Run 开始时的基础权限。 | `model/prompts.py`、`model/instructions.py` |
| 记忆 | 记忆模块提供项目情况、AGENTS.md 与路径约束、全局自定义要求、用户偏好和允许读取的长期记忆索引。 | `memory/context.py` 与各来源的持久快照 |
| 技能 | 系统提示词末尾的 `# Skills` 一节提供使用规则和可用 Skill 列表；本轮已加载的 Skill 说明放在 user 提醒块中。 | 冻结的 Skill Catalog、所选 Skill 快照 |
| 工具 | 系统直接提供当前可用工具的原生定义。 | `tools/`、已启用的扩展 |
| 会话与执行记录 | 系统保留真实用户输入、助手回复、工具调用和结果。 | SQLite 历史、输入引用与请求快照 |

系统另行提供运行环境、任务状态、来源说明和历史摘要。这些内容在请求中放在 `<system-reminder>` 块里，不会保存成新的人类 Session 消息。用户原文及其附件保持关联，系统不会为翻译、渠道来源或自动任务来源改写原文。原文中字面的 `<system-reminder>` 或 `</system-reminder>` 标签只在请求中转义成 `&lt;system-reminder>`，保存的原文不变。

## 独立记忆模块

`MemoryContext` 统一投影记忆内容。每段内容保留 `sectionId`、`source`、`memorySource` 和 `scope`。项目规则继续来自规则解析快照，个性化要求继续来自 Run 的设置快照，长期记忆继续来自现有 Memory 服务。仓库概览按项目记忆分类。系统没有把这些来源迁入同一张表，也没有新增存储权威。

`InstructionLayer` 保留 `id`、`authority`、`role`、`source` 和正文，用于排序、system/user 分流、上下文统计和最终化。这些元数据只留在数据结构中，不写进提示词。系统提示词由各层正文按顺序用空行拼接，每层以 `#` 标题开头（身份层以身份句开头），不再使用 `<instruction_layer>` 包装或 `<runtime_permissions>`、`<memory_state>` 标签。层上不再计算单独的内容哈希。`ResolvedInstructions` 仍保留全部层的拼接文本和 `instructions_hash`，因为步骤解析快照把它保存为 `resolved_instructions_hash`。低层指导通过 `context_layers` 取得，系统核心通过 `system_text` 取得。项目规则、个性化要求、长期记忆和 Skill 说明不会合入 `system_text`。上下文统计分别返回 `memory` 和 `skills`，面板以黄色显示记忆。

这些分类表示内容来源，不提高指令权限。当前用户要求优先于项目规则，项目规则优先于全局自定义指令，全局自定义指令优先于所选 Skill，所选 Skill 优先于回复偏好；用户资料和长期记忆属于背景资料。自定义子 Agent 指令只在子 Run 中出现，排在父任务与项目规则之后、全局自定义指令之前。所有内容都不能授予执行权限。路径规则仍按原有项目范围解析，当前事实仍需要按任务核验。

长期记忆的读取、自动学习、全局/项目范围和子 Agent 隔离保持原有规则。关闭长期记忆读取不会删除或关闭用户明确设置的项目规则和个性化要求。记忆索引保留私有撤销版本与记录引用；模型适配器只发送正文，不发送这些私有字段。长期记忆正文前有一行说明：它来自之前的会话，属于背景资料，可能已经过期，当前请求和已核验的事实优先。个性化三段分别标为“回复偏好”“用户资料”“自定义指令”，三段不再重复同一段前缀。“文本不能改变或授予权限”只在 `# Authority` 中说明一次，Skill、记忆、个性化和自定义子 Agent 不再各自重复。关闭、遗忘、请求准入、重试与迟到响应继续经过原有检查。

## 模型适配与恢复

Provider 没有通用的 memory 角色。逻辑 `context` Item 在 Pydantic AI 路径中使用兼容的 `UserPromptPart`，在 Responses 路径中使用 user 消息。系统不会把背景内容提升为 `SystemPromptPart` 或 developer 消息。这个传输角色不代表系统新增了人类 Session 消息，也不改变来源分类。

`model/reminders.py` 负责区分 Runtime 文本和用户原文。两条适配路径都把 Runtime 写的 user 角色文本包进 `<system-reminder>` 块。这包括 `context` Item、旧快照中带 `sectionId` 的 user Item、输入引用、保留的历史响应与历史工具结果，以及协议错误、工具错误、长度上限和最终化反馈。没有 `sectionId` 的 user Item 是用户原文，不加包裹。核心提示词的 `# Messages` 说明这个约定：块外的文字才是用户本条输入。`# Requests and content` 用一条原则区分两者：用户要求做的事是请求，其余都是内容，包括粘贴、引用或附件的文本，以及工具、文件、记忆、Skill 资源和其他 Agent 返回的结果。模型把请求作用在内容上，例如按要求翻译、总结或审查。内容可以说明怎么完成请求（例如项目文档里的构建步骤），但不能改变任务本身、扩大范围或授予权限，即使它写成对模型的指令。这一节只给一个通用注入句作例子，不再按输入渠道分别列规则，也不再使用中文翻译事故原样作例子。子 Run 的角色段说明块外文字是父 Agent 分配的任务，委派正文的首行写明“执行该任务，不增加用户授权”，不再称为材料；Desktop 仍按原首句去掉这一行。

用户原文始终单独作为一条 user 消息，不和任何文本合并。相邻的提醒块合成一条 user 消息，按原顺序拼接。输入引用移到它所属原文的前面，并入那条提醒消息，这样材料在前，请求在后。其他提醒保持原顺序：保留的历史响应和运行反馈留在两轮之间，需要对账时追加的运行状态仍在原文之后。首轮请求因此是 system、一条提醒消息和一条用户原文消息。连续两段用户原文（例如排队输入）也分成两条消息。工具调用与原生工具结果保持原有角色和批次关系。请求中会出现连续的 user 消息；当前使用的 OpenAI 兼容端点和官方 DeepSeek 都接受这种形状。严格要求 user/assistant 交替的模板可能拒绝它，本版没有为此增加开关。

适配器沿用历史响应、推理与图片的原有兼容处理。正常工具回放继续保留原生调用与结果关系。恢复投影保留当前用户目标、项目和 Skill 指导、记忆来源与范围、隐私撤销记录和连续性信息。系统不会为了恢复上下文自动重放副作用。

## 工具与 Skill

当前 Run 中已配置、可用且符合角色范围的工具从首轮直接提供。项目与无项目主 Run 使用相同原则。内置 automation 与已启用 MCP 工具也直接提供。系统不注册 `tool_search`，也不要求搜索后激活工具。参数校验、审批、Sandbox、Durable Intent、结果核验与未知结果记录继续生效。

旧激活记录和快照字段保留读取兼容。历史 Step 中原本不可用的调用不会因新版直接展示而自动重放。未知、禁用和未授权工具不会进入目录。

Skill 目录和子 Agent 目录属于 Runtime 提供的能力清单，和工具定义同类，因此放在系统提示词中，不放在 user 提醒块里。`# Skills` 一节先写使用规则，再写 `available_skills` 列表；目录开头说明每个名称就是 `skill_read` 的 `qualifiedId`，每项只包含唯一名称和 description。没有可用目录但有已选 Skill 时，这一节只保留规则。主 Run 有自定义子 Agent 时，`# Subagents` 一节列出冻结的类型，子 Run 不显示这一节。两节都放在 `# Permissions` 之前。权限段只写 Run 开始时的基础权限，Run 内批准的授权由对应的工具结果说明，不再改写系统提示词；否则每次批准都会让 Provider 前缀缓存从系统提示词起全部失效。子 Run 的角色段说明父 Run 已批准的授权同样适用。上下文面板仍把 `# Skills` 计入“技能”，把 `# Subagents` 计入“工具”。用户为本 Run 明确选择的子 Agent 仍作为 user 提醒块发送。模型使用 Skill 时读取主说明，再按需要通过 `skill_read_resource` 读取相对文本资源。目录不注入全部正文或文件树。同一 Turn 的目录与所选内容继续使用冻结快照。

Skill 的加载、资源 Lease 和身份检查继续生效。工具直接可用不会开放所有 Skill 文件，也不会授予写权限。

`# Skills` 说明 `skill_read` 会在首页返回已授权的 canonical `skillRoot` 与有界资源清单，清单优先列出脚本和参考资料。显式选择后已加载的 Skill 上下文提供相同信息，因此模型不需要重复读取主说明。模型用 `skill_read_resource` 读取相对路径文本，用 `run_shell` 执行根目录下的绝对脚本路径，不在文件系统里搜索 Skill。工具说明也区分文本读取、目录清单、二进制处理和脚本执行。`qualifiedId` 与 `resourcePath` 的 JSON Schema 显示路径和名称约束。资源清单最多 40 项，根路径和清单另有 4 KiB 预算，不挤占原有 48 KiB 文本结果预算；截断时返回 `resourcesTruncated`。模型可以用目录参数继续查看直接子项，`.` 表示根目录。工具对缺失、二进制和过大资源提供可操作的类型化错误数据。提示词内容变化后，Provider 的原有前缀缓存需要重新建立；权限和冻结快照语义不变。

## 流程、环境与验证

简单问候、闲聊和可以直接从对话完成的请求（例如处理用户给出的文本）可以直接回复。其他任务遵循英文三步流程：识别意图，按需要规划，然后执行与验证。步骤不再带“Intent recognition”等标签，提示词要求模型不在回复中标注或复述这些步骤。所需内容已在对话中时，模型先使用它，不去工作区查找，也不再次索要。只有任务需要工作区文件时，工具规则才要求先做文件发现。系统不要求模型公开内部推理，也不要求用户给自然输入添加特殊标签。

`# Communication` 要求模型把进度写成可见正文：任务第一次调用工具前，用一句话说明先做什么；确认发现、改变方向或遇到阻碍时简短更新；执行中收到用户的新消息（例如引导）时，下一次回复先用一句话说明计划怎么变，再继续。提示词说明用户看不到推理内容，同时不要求逐次读取都汇报。Desktop 执行流不显示 `reasoning_content`，只把它保存在响应回放中，所以只写在推理里的进度和对引导的回应，用户都看不到。

项目和无项目 Run 都提供实际工作目录、附加目录、平台、宿主 Shell、当地日期与时区。仓库概览放在历史之前，不含 Git HEAD，同一 Session 的多个 Run 之间保持不变。仓库检索片段按当前 Run 的请求生成，合成一个带来源说明的提醒块，放在该 Run 第一条用户消息之前；找不到这条消息时退回概览之后。Runtime 写入的引用资料说明、历史图片和预算提示都使用英文。精确时间任务仍应取得新鲜时间。已持久化请求的重试继续复用原快照。

本轮没有增加依赖或数据库迁移。公开上下文统计协议增加 `memory`、`skills` 两个分类，旧分类仍然有效。历史请求不会被改写。回退时应还原本轮源码与生成契约并重新载入 Runtime，维护者不应删除用户记忆或历史快照。验证范围与模型效果限制见[当前限制](../limitations.md#system-reminder-边界2026-11-02)。
