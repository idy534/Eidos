# 当前本地定时任务

Eidos 的定时任务在本机运行。SQLite 是计划、触发和执行来源的事实来源。实际执行使用普通 Run，继续遵守现有权限、取消、恢复和结果核验规则。Eidos 完全退出或电脑休眠时，任务不会执行。系统不检测漏跑，不补跑，不使用云端或额外守护进程。

## 管理与执行目标

侧栏的“定时任务”页面提供创建、查看、编辑、暂停、恢复、立即执行、删除和分页执行历史。历史关联普通 Run，展示等待、执行、终态与核验状态。用户可以打开对应 Session 查看回答、文件和审批。计划软删除保留 Session、Workspace 和历史。

左侧常驻“即将执行”和“已完成与暂停”两个分组。前者展示启用中的周期任务，以及尚未执行的一次性任务。后者展示暂停任务，以及已经触发的一次性任务。系统依据保存的 status 和 one_shot_fired 来源分组，不依据日期猜测执行结果。“已结束”表示一次性计划不再触发，具体执行结果仍以 Run 历史为准。搜索同时作用于两个分组，分页继续加载同一任务列表。用户暂停、恢复或收到任务变化通知后，列表会重新分组，并保留当前详情。已经删除的计划继续遵循现有隐藏规则。

模型只使用一个 deferred 工具 automation。模型先通过 tool_search 激活，下一 Step 再取得完整定义。mode 支持 view / create / update / delete / preview。view 有 ID 时读详情，无 ID 时分页查找。模型不能通过描述或配置文件代替保存操作。

创建时提供 sessionId，任务复用已有普通 Session。不提供时，任务每次触发新建 Session。projectId 字符串指定项目，null 明确无项目，省略则继承创建对话的项目。已有 Session 的项目从该 Session 解析，额外 projectId 必须一致。新会话支持 Local 或 Git Worktree，无项目任务使用独立私有 Workspace。工作树不默认带入未提交修改或联网 fetch。

任务保存已有模型 ID 与思考选择。每次执行重新验证配置并固定本次快照。approvalMode 默认 auto_review（替我审批），也可显式使用 manual（请求审批）。用户在页面手动创建或编辑计划时，还可以选择 full_access（完全访问）。选择后，页面显示现有的危险确认弹窗，并说明授权适用于该计划今后的每次执行。取消或按 Escape 后，审批模式保持原值；确认后，用户仍需保存计划。

Desktop 使用独立的请求类型接收三种审批模式。开启完全访问时，外层请求必须携带 fullAccessConfirmation: "full-access-v1"。Runtime 将确认版本随计划配置保存，并在每次接纳 Run 时传给既有的完全访问校验。普通编辑保留已保存的确认；切换到 manual 或 auto_review 时，系统清除确认。计划重启后继续使用已保存的模式。已有计划缺省该字段时继续保持原模式，不需要数据库迁移。系统只对完全访问配置保存该字段，普通模式保持原有配置形态。旧 Runtime 不能读取新的完全访问配置，Desktop 与 Runtime 需要一起更新并重启。

模型的 automation 输入仍只允许 manual 和 auto_review，也没有确认字段。普通对话中的模型不能修改完全访问计划的正文、时间、模型或执行目标，也不能重新启用此类计划；模型可以暂停、删除计划，或在更新中将模式降为 manual / auto_review。自动 Run 仍只能暂停自身计划。未来 Run 不继承其他 Run 的 Grant 或审批模式；完全访问只来自用户对该计划的手动确认。manual / auto_review 的自动审查失败、未知风险和高危人工请求继续沿用现有流程。所有模式继续保留参数、文件身份、版本、取消、Durable Intent、结果核验和未知结果记录。

自动 Run 在聊天中标为“定时任务自动执行”。它不改变用户下一轮的模型、工作模式或审批默认值。原会话使用已有上下文预算和压缩；新会话使用自足任务正文，不复制创建对话的完整历史或临时附件。

定时任务新建的 Session 只使用任务名作为标题，并遵守现有会话标题的长度限制。标题不再拼接时间戳、manual 标识或内部 ID。历史会话在读取时会对照当次计划快照和触发记录；标题仍与旧生成格式完全一致时，页面显示规范后的任务名。其他自定义名称继续保留，工作区目录不受显示名称影响。

Session 的可选 automationOrigin 复用现有自动执行来源契约。Runtime 通过原始自动 Run 与触发记录确认会话由定时任务新建，列表、详情和快照共用同一投影。已有普通 Session 被任务复用时，来源仍保持原样。会话行常驻显示 0.8rem 的定时任务图标，图形与侧栏定时任务入口相同。会话提示提供“会话来源：定时任务”链接，用户点击后直接打开对应计划的配置和执行历史。该入口支持不在当前任务列表页内的计划。

## 时间与占用

周期规则使用受限五段 Cron。固定间隔只允许 */10、*/30 和整点每小时三种。日历规则支持每天、每周指定日、每月指定日的一个时刻。系统拒绝秒、年份、月份限制，以及日期与星期同时限制。一次性任务使用带 UTC offset 的 at 时间，创建或重新启用时必须在未来。

时间模块使用 croniter、标准库 zoneinfo 与打包 tzdata。Eidos 只判断允许的规则形态和候选墙上时间。夏令时跳过不存在的本地时间。触发按 UTC 去重。预览、保存和调度使用同一时间计算。

一次性任务表单按所选地区时区显示和解释日期时间。Desktop 使用固定版本的 `@js-temporal/polyfill` 处理本地时间与 UTC 的转换。系统拒绝夏令时跳过的时间；同一本地时间出现两次时，用户必须选择带 UTC 偏移的第一次或第二次。用户编辑已有任务时，表单保留原来的重复时间选择。用户只改名称、正文或其他非时间字段时，系统保留原执行时刻及秒、毫秒精度。电脑时区变化不会让这些编辑附带修改执行时间。

任务列表日期、详情、执行历史、表单预览和工具卡片使用任务时区。历史使用当次执行快照的时区，避免当前配置改变旧记录的含义。完整时间显示 UTC 偏移和时区名称。工具预览没有提供时区、且结果没有任务信息时，卡片明确显示 UTC。

Runtime 在计划没有明确时区时读取 `TZ`，没有该变量时再读取系统地区时区。系统兼容 IANA 名称、带冒号的 IANA 名称、空值与 `UTC0`，以及 `CST-8` 这类整小时固定偏移；固定偏移会保存为 UTC 或等价的 `Etc/GMT` 名称。系统不会自行推断带季节规则或分钟偏移的 POSIX 名称，而会要求调用方明确提供地区时区。已保存计划继续使用原时区，系统时区变化只影响新计划的默认值。

Runtime 运行一个受 Supervisor 管理的 AnyIO 调度任务。每轮检查后，系统等待最近任务到期，最多等待五分钟。没有启用计划时，系统也每五分钟检查一次。已经到期的缓存会立即进入下一轮检查，读取异常仍沿用五秒重试等待。系统使用 AnyIO Event 和可取消的等待；跨线程通知只向现有 RuntimeAsyncKernel 的 asyncio 后端投递唤醒，不阻塞通知发送方。系统不创建每计划常驻线程或额外事件循环，慢环境准备继续使用已有 managed task。

用户通过页面或模型工具新增、修改、暂停、恢复、删除计划后，应用层会在 SQLite 事务提交后唤醒调度器，再发送 automation/changed 通知。通知传输失败不影响本机唤醒，通知重投也不会重复唤醒。系统在读取任务前注册等待事件，变更发生在扫描期间时，下一轮仍会重新读取。普通变更只按版本更新缓存，不重置无关任务的到期时间。Runtime 初始化完成时也会主动唤醒，避免服务等待完整的五分钟才开始检查。目标删除仍在原事务中暂停计划；调度器在下一次检查或到期时重读状态，最终入队检查继续阻止旧目标执行。

系统区分正常长等待与异常中断。调度器对照本次计划等待时长、墙上时间和单调时间；系统只在显式唤醒重算、时钟回拨、时钟偏差超过三十秒，或等待超出计划三十秒时清空时间缓存。正常的五分钟等待不会清空缓存。电脑恢复时，Desktop 沿用 schedule/refresh 请求，立即打断等待并重算未来时间。系统仍不执行旧时刻，也保留缓存触发迟到不足六十秒的接纳限制。

同计划未完成时不重叠。已有 Session 活动或排队时，本次触发跳过。任务在准备后发生版本变化时，旧准备不能入队。已接受 Run 保留自己的快照。一次性任务在 Run 入队的同一事务中停用；同版本触发仍在准备期间时，提前唤醒的检查不会将计划误判为过期。准备结束后，过期判断继续生效，失败不重新触发。原执行或重新生成的未知结果不再暂停所属计划。重新生成的自动 Run 也计入同计划占用。

## 持久化与工具链

Schema v28 新增 scheduled_tasks、scheduled_occurrences 和 automation_run_origins。普通启动和历史状态库升级都接入 v27→v28 迁移，失败回滚 DDL 与版本。任务配置采用严格类型，更新使用 expectedRevision。触发唯一键使用计划 ID 与计划时刻，立即执行使用稳定 operationId。

Renderer 经过 preload typed IPC 和 Main 调用 schedule/execute。command.mode 处理模型工具相同的管理用例，contextSessionId 只提供创建上下文。schedule/history、schedule/runNow 和 schedule/refresh 分别读取历史、手动触发和唤醒重算。Python Schema 通过 scripts/generate-automation-contracts.mjs 生成 Desktop DTO 与验证 Schema。

同一生成脚本使用已锁定的 Ajv standalone 生成静态校验器。Main 和 Renderer 共用这组校验器，保留字段限制、Unicode 字符长度、未知字段拒绝和禁止类型转换的规则。Renderer 加载定时任务工具卡片时不再动态编译 Schema，页面 CSP 继续禁止 JavaScript `unsafe-eval`。生产页面启动定向验证加载实际构建 HTML、CSP、bundle 和 sandboxed preload，并检查 React 启动页与控制台错误。

ToolSpec 保留 eidos_state 最大声明与 single 批次策略。可信内置 AutomationToolRuntime 在严格校验后解析本次实际类别；view / preview 使用 none，不提交 Intent，其余使用原写入流程。分类进入 DispatchPlan，不修改冻结 Registry。preserve_omitted_arguments 只对该工具开启并进入契约指纹，其他工具保留原默认参数行为。

写模式先准备候选配置，再通过 Controller 保存 Durable Intent。计划、操作回执和领域 Event / Outbox 原子提交，最终 ToolResult 仍由 Controller 提交。重启先检查可信内置来源与回执，恢复已知 SQLite 结果，不重新写入。取消后的已保存计划仍回显真实 ID、版本和副作用。未知外部操作保留原始结果，不阻止后续执行。

触发接纳在同一事务中复核版本、启用状态、占用、持久目标绑定和核验事实，并关联普通 Run 与自动来源。文件系统和 Git 准备在事务外完成。任务配置不成为另一套 Run 状态机。

## 来源与记忆

自动来源随触发入队原子保存，并供 Context、权限、UI 和记忆共用。自动输入不成为当下用户的新授权，不进入用户授权证据。SQLite 触发器将自动 Run 的已有和新建 Item 排除出自动学习。自动 Run 没有记忆写工具，读取仍遵守当前设置。同 Session 后续真实用户输入保持原行为。

周期自动 Run 只能暂停自身计划的原版本，不能创建计划、改正文、改时间或修改审批模式。版本冲突时不自动重试。子 Agent 不注册该工具。重新生成的逻辑请求与自动来源随新 Run 原子保存，创建防重沿用原逻辑请求。Fork 和 Checkpoint 不复制或撤销全局计划变更。

目标 Session 或 Project 删除时，系统在删除事务中暂停关联计划。独立任务不会因创建者 Session 删除而消失。缺失项目不会被解释为无项目。Worktree 继续使用现有 Snapshot、Retention 和 Restore，计划删除和结果已读均不清理产物。

## 容量恢复与未知结果（2026-10-19）

系统保留未知执行结果，但不要求用户核验，也不以此阻塞后续工具、子任务、定时任务、分叉、完成或取消。系统不自动重放不确定操作。工具错误和容量限制通过参数反馈、替代路径、短预览、分页和可取消重试恢复，不创建机器容量暂停或要求用户继续。权限、身份、版本和真实结果校验继续生效。模型上下文移除工程校验 Hash；原始结果、内部完整性和 UI 分页校验仍保留。详细规则见[当前架构](../architecture.md#容量恢复与未知结果2026-10-19)。
