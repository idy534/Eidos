# 当前记忆系统

记忆保存可跨会话复用的偏好、决策、连续性状态、已验证经验和事件。它是带来源的历史资料，不授予权限，也不替代当前用户指令或实时事实。

## 权威与发布

`state.sqlite` schema v21 保存作用域、不可变版本、证据、操作、抑制记录、作业、预算、使用记录、快照引用及派生 generation。v16→v17→v18→v19→v20→v21 通过既有入口分阶段在事务内升级。v19 保存 Root 会话的 use epoch，升级时推进作用域 epoch，撤销未绑定会话资格的旧记忆快照和工具载荷，旧工具正文在清理前也不能进入新请求。v20 保存历史整理的 `backfill_until` 上限，结束旧的无范围回填授权并取消旧待执行模型作业，保留已保存条目、设置与证据。v21 仅扩展子 Agent 角色约束，保留这些记忆事实。正文位于数据目录的 `memory/` 下，使用服务端 UUID，不按正文哈希命名。

私有目录与文件使用目录 FD、`O_NOFOLLOW`、普通文件/硬链接校验、临时写入、fsync 和原子 rename。发布事务重新检查来源、租约、版本 CAS 和 privacy epoch；未提交文件不会成为可读事实。读取检查保存的大小与 mtime，缺失或变更正文 fail closed。这不能发现主动保留大小及 mtime 的恶意篡改。

FTS、摘要与目录是可重建投影。旧 `memories.sqlite` / MemoryStore metadata 接口保留兼容，不是新记忆业务的第二个权威。孤立 Markdown 按小时扫描，保留一小时宽限，保护正在准备的文件，单次最多扫描十万项。

## 控制与来源

| 写入模式 | 授权条件 | 新条目结果 |
| --- | --- | --- |
| `automatic` | 当前作用域开启自动学习，来源处于授权时间窗口，有明确证据 | 直接成为 `active` |
| `candidate` | 共用同一作用域开关和时间窗口，内容需要用户确认 | 保持 `candidate`；用户接受后才成为 `active` |
| `remember` | 用户明确要求保存，沿现有 Run 审批或直接设置操作授权 | 明确内容成为 `active`，不依赖自动学习开关 |

Runtime 不按证据类别把一个写入模式隐式改为另一个模式。

| 控制 | 默认值 | 语义 |
| --- | --- | --- |
| 使用记忆 | 开启 | 允许使用已生效的授权记忆 |
| 自动记忆 | 关闭 | 用户确认后，当前 Run 可保存本作用域中开启之后的明确长期信息；候选写入也受此开关约束 |
| 历史回填 | 不自动执行 | 单独选择当前会话并确认 |
| 临时会话 | 关闭 | 开启后禁止本会话使用、写入和学习 |
| 每日历史整理调用 | 20 次 | 包括失败与格式重试；前台事实核查复用当前 Run 的模型，不计入历史整理配额 |
| 每日 token | 100000 | 保守预留，获得 usage 后调整 |
| 去抖兼容字段 | 300 秒 | 保留旧设置契约；即时保存和用户选择的历史整理不等待去抖 |

关闭生成不会删除现有记忆，但取消相关任务并结束旧历史回填授权。再次开启跳过关闭期间资料；临时状态切换也撤销旧回填授权。用户可以显式重新选择历史。

当前作用域开启自动记忆后，模型可以在当前 Run 调用 `memory_record(mode=automatic)` 保存有真实证据、能改善未来相关任务或减少用户重复说明的信息，Run 等待工具结果。Runtime 在 Durable Intent 前检查当前作用域、开启时间窗口、真实来源及更新目标，并在发布事务中复核设置、来源版本、privacy epoch、CAS 和取消状态。用户一次开启只授权当前作用域，`full_access` 不会开启自动记忆。Projectless 的当前作用域是全局，Project 开关不会影响 Projectless 会话。

前台与历史整理共用通用的长期价值规则，内容类型只是组织方式，不是可记忆事项的白名单。模型可以从一次明确陈述识别长期做法，无需用户重复或专门要求保存。每条记忆应简短，并保留用户表达的适用范围、条件和证据。模型应跳过重复、临时、通用及无后续价值的信息，不能把单次要求、假设、角色扮演或第三方陈述扩大为长期用户偏好。`automatic` 只保存有明确证据的事实并直接生效，不能隐式转为候选。`candidate` 是独立的待确认流程，只有用户通过接受操作确认后才生效；`inferred` 只能通过候选流程提交。明确习惯、已确认决定和已验证事实不因来源 Run 是 Plan 而自动变为候选。前台自动与候选模式均只允许开启之后的资料，历史整理授权不会扩大前台时间窗口。用户明确请求独立保存时，`mode=remember` 继续按 Run 审批模式授权；关闭使用或自动记忆不妨碍此路径。

自动保存记录使用独立的 `automatic` 操作类型。Runtime 在 Intent 前拒绝非候选模式的推断证据，返回 `memory_confirmed_evidence_required`。去重复用也必须保留模式对应的状态；候选不能因匹配到 active 条目而自动生效，自动流程不能复用未确认候选。已有操作重试仍返回原结果，不改写旧条目。前台模型通过记忆检索判断同作用域事实是否重复，类型只用于组织内容。模型认为事实未改变时，应保留已有正文与有效时间，并提交已有 ID 和版本；Runtime 按正文与有效时间复用原 ID 和版本。正文及有效时间完全相同的 active 条目仍有确定性的去重检查。模型可以用 `targetEntryId` 与 `expectedRevision` 对明确事实更正提出版本更新；Runtime 拒绝跨作用域、过期版本及候选覆盖。自动流程不能覆盖固定项、用户拥有条目或显式管理过的内容。操作重试保留原结果；旧格式操作记录仍可按相同语义重放。

全局/Project 范围由服务端稳定身份决定；不同 Project 不能通过任意客户端 ID 跨界读取。Projectless 使用全局范围，Child 沿 Root 的授权只读访问。自动保存以 Root 来源为单位，不把 Project 惯例自行升格为全局偏好。

类型为 preference、decision、continuity、experience、event。状态为 candidate、active、superseded、archived、quarantined、forgotten。有长期价值但其内容仍待确认的提议、推断和假设保持候选。对“某提议尚未采纳”等已确认讨论状态的忠实 continuity 记录可以生效，但不能把提议本身当成工作规则。用户接受、纠正和独立保存形成用户控制版本；自动保存和历史整理不能覆盖固定项或用户明确控制的正文。

证据必须是当前 Root 中真实完整的用户资料，或成功的普通工具结果。Assistant 输出、记忆工具结果、不完整/修订/删除/临时来源、抑制来源不构成自动学习证据。模型候选携带原文精确引用，不能仅用来源 ID 或模型自述证明。

管理使用 `expectedRevision` CAS 与稳定 `operationId`。同一 ID 不能提交不同内容；重试返回原结果。模型提出的“已获授权”不能绕过已有审批。

## 检索、投影和撤销

检索使用 FTS5 unicode61、可用时的 trigram、标题/别名、短词片段及 RapidFuzz 重排，不依赖向量模型。查询表达式安全构造，短词和历史扫描有候选上限，响应提供 truncated 与 cursor。查询页保留相关性排序；游标同时保存最多 500 个候选窗口的位置和窗口内的排序偏移。FTS5 先按 BM25 生成排名，SQLite 完成融合后才截取候选；短词和历史查询仍分窗口扫描。翻页应保持查询和过滤条件不变，期间增删改记忆可能改变排序。默认读取当前 active 正文，历史查询读取具体不可变版本和有效时间。启动可恢复遗失索引，UI 也可显式重建。

| 内置工具 | 行为 |
| --- | --- |
| memory_search | 授权范围内有界检索，可请求历史，支持 cursor/next_cursor |
| memory_read | 按 ID/revision 读取正文及来源，最多 4096 字符 |
| memory_record | 当前 Run 自动保存合格事实、提交候选、按用户明确请求保存，或用目标 ID/revision 更新已有事实 |
| memory_manage | 受控接受、纠正、固定、归档、遗忘，使用版本 CAS |

每 Run 最多三次检索/读取、累计 16384 字节；同一工具重试不重复扣费。实际读取记录 read 并更新使用次数；仅投影记录 served。cited/applied 类别预留，当前不从自由文本猜测引用或应用。

模型提供逐字 `sourceQuote` 时，Runtime 在当前会话最近 32 条对应类型的完整来源中查找；当前 Run 的匹配来源优先，历史匹配必须唯一。来源更旧或存在歧义时，模型可使用已有的 `sourceItemIds` 与 `sourceQuotes` 指定来源。Runtime 分别检查用户陈述和 `observed_verified` 的成功普通工具结果；Assistant 输出、失败或不完整工具、记忆工具结果及其他会话资料不能充当事实证据。引用必须指向事实原文，后来的保存请求仅表达授权。正文等于原文时可省略引用。

前台模型负责判断记忆的未来价值、正文是否忠实、适用条件、单条事实组织和语义匹配。Runtime 不为 `memory_record` 或 `memory_manage(correct)` 再调用一次模型审核，也不把模型审核格式、理由长度或作用域的整体 generation 作为前台保存门槛。Runtime 仍核对来源资格、逐字引用、作用域、授权时间窗口、目标版本、敏感内容、取消与撤销状态。逐字引用命中只证明来源存在，不能证明模型改写的正文准确。当前有界检索也不能保证找到所有改写的旧事实。系统没有批量拆分或改写旧条目。

Runtime 在授权和 Durable Intent 前解析引用、捕获来源版本，并核对来源资格与目标版本。发布事务继续比较授权前的来源版本，不能在授权后重新捕获版本来接受中途修订的来源。正文和有效时间完全相同的自动保存仍在发布事务内去重；显式目标更新继续使用 CAS，并保护固定项和用户控制内容。来源、授权或取消状态变化会拒绝发布。旧工具结果中的事实审核 DTO 仅用于读取历史记录，新保存不生成审核结论。日志只记录 Run、Item、工具名和错误码。

常驻投影最多占可用输入预算的 3%，不超过 1200 个保守估算 token。偏好、决策、连续性提供短摘要，经验提供标题与 entryId@revision 路由；所有成本进入 ContextBudget。固定使用策略来自 Runtime，正文使用独立的历史任务资料 section。

前台 developer 提示要求按记忆所述范围与条件使用默认信息，当前用户指令和已验证现状优先，不能从记忆推导额外要求、禁令、审批步骤或权限。前台提示按当前生成开关分开生成：关闭时只描述显式保存与管理，不注入自动或候选保存指引；开启时分别说明 automatic 的直接生效语义和 candidate 的待确认语义。两种流程继续共用当前作用域的授权开关和开启时间窗口。前台保存与历史模型提炼共用 `MEMORY_LEARNING_INSTRUCTIONS`，按未来价值、证据和适用条件判断，不列举必须保存的姓名或具体习惯。参数、模式和分页说明放在工具 Schema；后台提炼规则由独立的 MemoryModelExecutor 提供。Runtime 在每个 Step 从 SQLite 读取当前访问资格。有记忆工具、摘要或临时状态的请求包含短的 memory_state：当前作用域、允许读取的范围、本会话的自动生成开关和临时状态。该状态只描述设置，不证明模型已经调用保存工具或记忆已经生效。Child 不生成自身记忆。

工具列表随当前资格刷新。临时会话不暴露记忆工具；没有允许使用的作用域时，Runtime 不暴露检索与读取工具。关闭使用或生成不影响 Root 用户明确请求直接保存或管理记忆。用户明确设置未来行为已经表达保存请求，不要求额外说出“请记住”。Child 只暴露已获授权的读取工具，也不收到写入规则。工具隐藏只减少错误调用；服务端仍执行原有作用域、来源、审批、版本与撤销校验。

快照保存具体版本、generation 和 exact epoch。持久化、读取、协议修复、重试、最终化及请求准入均复核作用域 privacy epoch 和会话 use epoch。临时模式切换会推进 Root 的使用版本，同时撤销 Child 的旧上下文；其他会话的独立记忆不受该使用版本影响。源资料失效或隐私撤销会取消请求；忽略取消的迟到响应也丢弃，下一步重新构建合法输入。历史记忆工具的参数和结果一起阻止再次发出，不等待物理清理。

Context Usage 只查询已持久化的 Plan 预算和 Provider 用量，不读取快照正文。正文撤销或清理不影响这些统计数字的查询。数字表示最近一次已构建或请求的大小，新合法上下文生成后再更新；统计查询不允许读取或重新使用被撤销的记忆正文。

来源修订、Run 重写、Session 删除、Checkpoint 回退会在来源变更事务中隔离关联非用户拥有条目并推进 epoch。混合来源先隔离，当前 Run 或用户再次选定的历史整理可从剩余有效原始资料重新派生；来源失效本身不触发后台学习。Fork 记录 lineage，不复制原证据授权。

遗忘移除所有正文版本和派生投影，撤销执行快照，清理直接关联的操作记录、工具/审批正文和任务载荷，保留最小 suppression，防止同一旧来源复活。它不删除原始聊天，不撤回已发给 Provider 的资料，也不控制外部导出、自然语言复述或旧备份。用户独立保存的版本按自身授权处理。来源失效后的清理会同时擦除对应版本的 memory_actions 请求正文，并保留 operationId、结果和必要审计标识；旧版本已删或文件清理重试时也执行该擦除。用户独立纠正后的有效版本按自身授权保留。

## 后台服务

唯一常驻服务由 RuntimeAsyncKernel、RunSupervisor 和资源注册表管理，负责文件清理、派生投影维护和用户显式选择的历史整理。普通新对话不会创建后台模型作业。历史整理处理终止状态 Root 会话，向前台运行、活跃 Child 与重配置让出。有限任务等待不包含永久服务，Runtime 关闭仍统一取消并等待资源清理。

历史选择捕获当前已有资料的序号上限，并持久化 `backfill_until`。自动记忆关闭时用户仍可单独选择历史；临时或 Child 会话禁止选择。后续消息不会进入旧授权，多窗口作业只处理上限之内的资料。完成、关闭自动记忆或切换临时状态会结束相关授权。新作业使用 policy version 2，旧无范围作业不会恢复执行。

作业持久化 source revision、frontier、长条目 offset、epoch、base generation、模型 ID 和非敏感配置快照。窗口最多 32 条 / 64 KiB，每条分段覆盖，中间内容不会因仅保留开头而永久丢失。

两阶段先抽取原文证据，再把原始资料、候选与最多 32 条相关旧记忆一起交给整理请求。整理请求必须检查最终发布内容，并明确返回 grounded 与 atomic。缺少这两个字段的旧结果默认不具备发布资格。历史整理保留这项整理结果检查；前台保存只执行来源、授权与提交校验，不另发模型核查请求。抽取的 `requiresConfirmation` 表达内容是否仍需确认，独立于证据类型和来源 Run 模式；只有支持充分的事实和已采纳决定才能设为 false，`inferred` 仍保持候选。旧抽取结果缺少此字段时默认保持候选。未确认条目不能覆盖已有条目。抽取结果可复用；proposal 目标、候选覆盖、来源和 CAS 均严格验证。文件在事务外准备，版本、证据、索引、generation 和任务进度在事务内发布。

后台复用 ModelGateway lease，没有工具执行权限、独立 HTTP 客户端或新 Agent Loop。隐藏 HTTP 重试关闭，格式修复最多一次，失败调用仍记账。租约可恢复，有界退避，预算耗尽暂停至下一个 UTC 日。配置删除或变更进入 blocked_model，用户显式用当前配置重试，不自动切换 Provider。

`memory.changed` 元数据 Event/Outbox 与业务变更同事务提交。设置页在首次打开、作用域或筛选变化、操作成功、窗口重新获得焦点和用户点击“刷新记忆”时读取当前数据。搜索输入等待 250 毫秒后再读取，连续输入只查询最后一个值。空闲页面不定时读取。页面发现 queued/running 历史整理任务时，在前一次读取结束五秒后再读取；retry_wait/paused_budget 按 notBefore 安排刷新，最短间隔五秒。任务终止或模型配置阻塞后，页面停止定时读取。页面隐藏时暂停请求，恢复可见时刷新。页面卸载和筛选变化会清理定时器，并丢弃旧请求的迟到结果。当前没有向 Renderer 推送记忆变更通知或正文的路径；其他会话保存的记忆由手动刷新、重新打开页面或窗口恢复时读取。

## Desktop、备份和验收

设置页提供范围、独立使用/生成开关、临时模式、手动保存、候选确认、搜索分页、历史版本、来源跳转、纠正/固定/归档/遗忘、预算、任务状态、重试、索引重建、导出与完整备份。旧版本管理按钮不能修改当前版本。搜索列表提供短预览；纠正前读取完整当前版本，并用该版本执行 CAS，读取失败时不打开编辑框。

Python 严格 DTO 是共享契约来源；`node scripts/generate-memory-contracts.mjs` 生成 TypeScript 类型与 JSON Schema。Main 使用 AJV2020 校验白名单请求/响应，preload 暴露 typed IPC。备份路径只由 Main 原生保存对话框选择，Renderer 不能自由指定。

Markdown 导出仅当前页，并提供截断提示；页内包含完整正文，历史搜索导出对应的具体版本。完整 ZIP 一致复制 SQLite、所有被引用记忆/派生文件与执行 Blob，核对引用、文件与 epoch 后原子发布。Provider 配置和 Workspace 不包含在内。ZIP 包含私有聊天，可能含 MCP 环境配置，未加密。
